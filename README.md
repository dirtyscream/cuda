# Лабораторные работы: параллельное программирование

## Лаб. 1 — блочное умножение матриц и векторизация

Умножение двух блочных матриц тремя способами со сравнением результатов и
производительности:

- **скалярная** версия — векторизация отключена флагами сборки, эталон сравнения;
- **C1** — автоматическая векторизация, тот же исходник кернела;
- **C2** — ручная векторизация на интринсиках SSE2.

C1 и C2 обязаны совпадать **побитово**, а C2 не должна быть медленнее C1.

### Особенность

Целевая машина — Apple M5 (ARM64), где инструкций SSE2 физически нет. Ядро
написано на настоящих интринсиках SSE2 и транслируется в NEON на этапе
компиляции через [sse2neon](https://github.com/DLTcollab/sse2neon). Тот же файл
собирается под x86_64 без единой правки и порождает `mulpd`/`addpd`.

Транспонирование матриц запрещено условием задачи, поэтому используется схема
broadcast-and-accumulate из Intel AP-930: элемент A размножается по дорожкам
вектора и умножается на строку B, которая читается подряд.

### Сборка и запуск

```bash
cd lab1
make          # Release, -O3
make run      # три версии, проверки, тайминги
```

### Цели Makefile

| Цель | Что делает |
|---|---|
| `make` | нативная сборка |
| `make run` | три версии, проверки корректности и скорости |
| `make report` | замечания оптимизатора о векторизации |
| `make disasm` | счётчик векторных и скалярных инструкций |
| `make prove` | какой из двух векторизаторов порождает векторный код |
| `make x86` | кросс-сборка под x86_64 |
| `make x86-run` | запуск x86-версии через Rosetta |
| `make x86-disasm` | инструкции x86 и ARM бок о бок |
| `make clean` | удалить `build/` и бинарник |

### Результаты (Apple M5, матрицы 4000 × 4000, `double`)

| Версия | Время | Ускорение |
|---|---|---|
| скалярная | 7,48 с | 1,00× |
| C1 — автовекторизация | 3,84 с | 1,95× |
| C2 — SSE2 | 3,80 с | 1,97× |

Теоретический потолок для `double` на 128-битном регистре — 2,00×.

## Лаб. 2 — оптимизация доступа в кэш

Векторное ядро из лаб. №1 в исходном порядке блоков (C1) против той же арифметики,
оптимизированной под кэш (C2): подматрицы по формуле задания для L2 и L1, результат в
регистрах; для сравнения — скалярная C0. Матрица матриц сохранена, результаты
совпадают побитово на случайных дробных данных. На одном ядре C2 быстрее C1 в
**1,56–1,71 раза** и скалярной версии — в **2,32–2,61 раза** (с FMA — 2,14 и 2,83).

```bash
cd lab2
make run     # C0, C1, C2: проверки и таблица результатов (~50 с)
make probe   # задержка загрузки по размеру рабочего множества: L1 0,68 нс, память ~86 нс
```

Подробности — в `lab2/README.md` и `lab2/docs/lab2-theory.pdf`.
