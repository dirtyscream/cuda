# Лаб. 2 — оптимизация доступа в кэш

Берёт векторизованное ядро из лабораторной №1 и, **сохраняя матрицу матриц**, оптимизирует
доступ к памяти под иерархию кэшей. Строка задания «матрицу матриц можно удалить» зачёркнута.

**Блок** — матрица 10 × 10 из лаб. №1. **Подматрица** — прямоугольник из целых блоков, который
держится в кэше (в формуле задания он назван блоком).

## Версии

| Версия | Что это |
|---|---|
| C0 | скалярная база: простое ядро лаб. №1, собранное без векторизации, блоки i → j → k |
| **C1** | ядро SSE2 из лаб. №1 без изменений, блоки в исходном порядке i → j → k — только векторизация |
| **C2** | та же арифметика: подматрица B в L2, блоки A и столбец B в L1, 5 строк результата в регистрах |

Все три работают на одном потоке. Данные — случайные `double` из [−1, 1): на них суммы
округляются, и совпадение **побитово** (`memcmp`, без epsilon) доказывает одинаковый порядок
операций. На целых числах оно не доказывало бы ничего — их суммы точны в любом порядке.

## Сборка и запуск

```bash
make          # Release, -O3; раздельные умножение и сложение, как в лаб. №1
make run      # C0, C1, C2: проверки и таблица результатов (~50 с)
make probe    # задержка загрузки по размеру рабочего множества, случайно и подряд
make disasm   # арифметические инструкции в каждом ядре: векторные и скалярные
make FMA=1    # все ядра на слитом умножении-сложении (make clean перед сменой режима)
LAB2_DEPTH=384 LAB2_WIDTH=384 make run   # C2 без подматриц: только регистры
```

## Устройство C2

- **Формула задания на двух уровнях.** `floor(L / 3 * 0.9)`: для L1d (128 КиБ) это 39 321 байт —
  глубина подматрицы 48 блоков; для L2 производительного кластера (16 МиБ, роль L3 — на Apple
  silicon L3 нет) это 5 033 164 байта — ширина 128 блоков. Подматрица B — 48 × 128 блоков
  (4,9 МБ); она неизменна, пока мимо неё проходят все строки блоков A.
- **L2.** Внутри подматрицы порядок тот же, что у C1, — i → j → k, и спуск по столбцу B идёт с
  прыжками, но попадает в L2, а не в память. Каждый кусок B читается из памяти один раз.
- **L1.** 48 блоков строки A нужны для всех столбцов подматрицы, столбец подматрицы B — для
  обеих половин блока результата: по 38,4 КБ.
- **Регистры.** Пять строк блока результата — 25 аккумуляторов — остаются в регистрах на всю
  глубину подматрицы, 48 произведений блоков подряд; C загружается и сохраняется раз на подматрицу.
- **Ширины** подматриц кратны 8 блокам: 640 байт как матрица и 6400 байт в памяти — кратно
  и 64 (задание), и 128 (линия M5).
- **Без копирования и транспонирования.** Блоки B читаются на месте.

## Результаты (Apple M5, 384 × 384 блока 10 × 10, `double`, один поток)

| Версия | Время | GFLOP/s | к C0 | к C1 |
|---|---|---|---|---|
| C0, скалярная | 8 607 мс | 13,2 | 1,00× | 0,66× |
| C1, векторная (лаб. №1) | 5 719 мс | 19,8 | 1,50× | 1,00× |
| C2, оптимизация под кэш | 3 398 мс | 33,3 | **2,53×** | **1,68×** |

По пяти прогонам C2 / C1 = 1,56–1,71×, C2 / C0 = 2,32–2,61×. С `FMA=1`: 2,14× и 2,83×.

Вклад частей C2, измеренный отдельно: регистры ≈ 1,24–1,34×, подматрицы ≈ 1,19–1,32×
(с FMA 1,41× и 1,56×). Без FMA C2 упирается в потолок арифметики одного ядра (~33 GFLOP/s) —
туда же приходит и программа лаб. №1 в её порядке i → k → j; с FMA C2 быстрее её в 1,34–1,38 раза.

Замеры снимать от сети, с выключенным режимом низкого энергопотребления и не в фоне.
